# Спецификация: Импорт «сырых чертежей»

> Как загружать необработанные планировки и превращать их в красивый план.
> Парсер: `src/utils/blueprintParser.js`. Стор: `src/state/BlueprintStore.js`.
> UI: `src/components/Controls/ImportPanel.jsx`.

## 1. Идея

Пользователь загружает «некрасивый чертёж» — упрощённый JSON, где комнаты описаны
**прямоугольниками** (`x, y, w, h`), а объекты — парой координат. Парсер валидирует данные
и нормализует их в полный контракт `Building` (`specs/data-model.md`), после чего
существующий SVG-рендерер отрисовывает план в стиле Modern Minimal (градиенты, тени,
пастельные заливки).

Мок «Меридиан» (`src/data/building.js`) остаётся запасным зданием и не изменяется.

## 2. Формат входного JSON

```jsonc
{
  "name": "Здание",                    // необязательно; иначе «Здание без названия»
  "bounds": [1000, 640],                 // необязательно; система координат этажа
  "floors": [
    {
      "level": 1,                        // необязательно; иначе порядковый номер
      "name": "1 этаж",                  // необязательно; иначе «Этаж N»
      "outline": [[80, 60], [920, 60],   // необязательно; контур корпуса сложной
                  [920, 400], [500, 400], // формы (Г-образный). Без него внешняя
                  [500, 580], [80, 580]], // стена рисуется по bbox комнат
      "rooms": [
        {
          "name": "Холл",                // необязательно; пустое/отсутствует = без подписи на плане
          "type": "hall",                // обязательно: один из RoomType
          "x": 80, "y": 60,              // левый верхний угол
          "w": 340, "h": 210             // ширина и высота (положительные)
        }
      ],
      "objects": [                       // необязательно
        {
          "type": "elevator",            // обязательно: один из ObjectType
          "x": 140, "y": 320,
          "name": "Лифт №1",             // необязательно; дефолт по типу
          "status": "working",           // необязательно; дефолт по типу
          "details": { ... }             // необязательно; мержится с дефолтами
        }
      ]
    }
  ]
}
```

### Типы комнат (`RoomType`)
`hall`, `office`, `meeting`, `server`, `service`, `cafe`, `corridor`, `lift` — строго из
`specs/data-model.md` (палитра — `specs/design-system.md`).

Необязательное поле комнаты `polygon` (массив `[x, y]`) задаёт форму напрямую —
для скошенных стен. Без него форма строится из `x, y, w, h`.

Необязательное поле комнаты `gradient` (`'graphite-1'…'graphite-3'`) задаёт
заливку явно — когда смежные комнаты одного типа надо различить по тону.

### Типы объектов (`ObjectType`)
`elevator`, `stairs`, `camera`, `atm`. Дефолтные значения:

| Тип | Статус по умолчанию | Дефолтные `details` |
|---|---|---|
| `elevator` | `working` | `{ capacity: '1000 кг', lastService: '—' }` |
| `stairs` | `working` | `{ kind: 'Пожарная', floors: 1 }` |
| `camera` | `online` | `{ angle: 90, direction: 90, ip: '—', recording: true }` |
| `atm` | `active` | `{ cash: '—', currency: 'RUB' }` |

## 3. Что делает парсер

`parseBlueprint(raw)`:
1. Валидирует структуру (этажи, комнаты, объекты, координаты, типы) — при ошибке бросает
   `Error` с понятным русским сообщением.
2. Превращает прямоугольник комнаты в полигон из 4 точек (по часовой стрелке).
   Контур этажа (`outline`) пробрасывается как есть — по нему рисуется внешняя
   стена (`FloorPlanSvg` → `BuildingOutline`); при его отсутствии берётся bbox.
3. Генерирует ID: этаж `fN`, комната `fN-rN`, объект `fN-<prefix>N` (prefix: `e`, `s`, `c`, `a`),
   нумерация объектов — сквозная по типу в пределах этажа.
4. Заполняет дефолты (имена, статусы, детали) и сливает переданные `details`.

Вспомогательные экспорты:
- `validateBlueprint(raw)` → `{ ok, message }` — без исключений, для UI-подсказок.
- `blueprintSummary(building)` → строка-резюме («этажей N, комнат N, объектов N»).

## 4. Стор `BlueprintStore`

- `building` (computed) — активное здание: актуальный чертёж, если он есть и
  включён (`showDrawing`), иначе мок «Меридиан».
- `importText(text, source?)` — парсит JSON-строку; при успехе подменяет здание и
  переключается на первый этаж (`ui.setActiveFloor`); при ошибке — `lastError`.
- `importFile(file)` — читает файл через `FileReader` и вызывает `importText`.
- `acceptConverted(raw, source)` — принять результат конвертера напрямую, минуя
  JSON: чертёж сразу доступен на основном плане.
- `toggleDrawing()` — вывести чертёж на план ↔ вернуть «Меридиан». В сайдбаре
  это переключатель «План: Меридиан | Чертёж». Импорт при этом не сбрасывается.
- `clear()` — возвращает здание по умолчанию («Меридиан») и стирает импорт.
- `hasDrawing`, `showsDrawing`, `importedFrom`, `lastSummary` — состояние для UI.

> Чертёж живёт в памяти: после перезагрузки страницы его нужно загрузить или
> сконвертировать заново.

## 5. Ограничения первой итерации

- Только прямоугольные комнаты; произвольные полигоны — в формате самого проекта
  (`src/data/building.js`), импорт полигонов можно добавить позже.
- Двери/окна в «сыром» формате не передаются (опциональное расширение).
- Импорт растрового изображения (скана чертежа) — Roadmap (см. `README.md`).
