# make-stage.md — Процесс создания этажа из скриншота

> Строгий, воспроизводимый процесс: пользователь даёт **скриншот/изображение плана
> помещения**, агент анализирует его и перерисовывает **в едином стиле приложения**,
> превращая в новый этаж (`src/data/building.js`). Цель — каждый раз получать этаж,
> визуально неотличимый от существующих, с корректной геометрией и объектами.

---

## 0. Принцип работы (кратко)

```
 Скриншот плана  →  Анализ (AI vision)  →  Геометрия (полигоны)  →  Данные этажа
                                                                      ↓
                                                    building.js → проверка в браузере
```

1. Пользователь прикрепляет изображение плана помещения + сообщает **номер этажа** и
   **название** (например: «4 этаж — Офисы»).
2. Агент анализирует изображение: выявляет комнаты, стены, двери, окна, особые объекты.
3. Агент переводит это в **координатную сетку приложения** (1000 × 640) и формирует
   полигоны комнат + объекты.
4. Агент добавляет этаж в `building.js`, проверяет (lint + браузер) и сообщает результат.

---

## 1. Что агенту нужно знать о системе координат

Этаж рисуется в SVG `viewBox="0 0 1000 640"`. Все координаты — в этой системе.

### Периметр здания (внешние стены)
- **X:** 80 … 920 (полезная ширина 840)
- **Y:** 60 … 580 (полезная высота 520)
- Внешние стены рисуются автоматически (`BuildingOutline`) по bounding box всех комнат.
- От пола/потолка до края viewBox — поля 60px сверху, 60px снизу — для подписей/воздуха.

### Сетка привязки
- **Все координаты кратны 10** (округлять до 10). Это даёт чистые примыкания комнат.
- Комнаты **примыкают вплотную** (общие рёбра без зазоров и наложений).

### Типовая ширина коридора
- Коридор — горизонтальная артерия высотой **120** (обычно Y 270…390).
- Вестибюль/холл могут сливаться с коридором (стена убирается через `wallGaps`).

## 2. Этапы процесса

### Этап 1 — Сбор входных данных
Агент получает от пользователя:
- **Изображение** плана помещения (скриншот, фото, схема).
- **Номер этажа** (`level`) и **название** (`name`, например «4 этаж — Офисы»).
- (Опц.) список особых объектов, которые надо расставить.

Если данных мало — агент спрашивает. Не додумывает планировку произвольно.

### Этап 2 — Анализ изображения (AI vision)
Агент **детально описывает** изображение (через `analyze_image` или аналогичный инструмент):

1. **Комнаты:** перечень, примерные пропорции и взаимное расположение.
2. **Коридоры:** где проходит, ширина.
3. **Двери:** где расположены (между какими комнатами / выходы наружу).
4. **Окна:** на каких внешних стенах.
5. **Особые объекты:** лифты, лестницы, камеры, банкоматы, санузлы.
6. **Внешний контур:** прямоугольный / сложная форма.

**Правило:** лучше задать **два** промпта анализу —
- первый: общая структура и подписи комнат;
- второй: двери/окна/объекты.
Так полнее и точнее покрытие.

### Этап 3 — Перенос в координатную сетку
Агент переводит выявленную структуру в координаты 1000 × 640.

**Алгоритм:**
1. **Внешний контур** → вписать в рамку X 80…920, Y 60…580 (если план прямоугольный).
2. **Коридор** → горизонтальная полоса высотой 120 (Y 270…390), если есть.
3. **Комнаты** → перенести пропорционально, округляя координаты до 10.
4. **Примыкания** → проверить, что соседние комнаты делят общие рёбра (нет зазоров).
5. **Двери** → координата на стене + `side` ('top'/'bottom'/'left'/'right').
6. **Окна** → на внешних стенах, координата + `side`.
7. **Объекты** → координаты внутри нужной комнаты + `roomId`.

**Контрольный чек-лист переноса:**
- [ ] Все комнаты вписаны в периметр 80…920 × 60…580.
- [ ] Координаты кратны 10.
- [ ] Соседние комнаты примыкают (общие X/Y на стыках).
- [ ] Нет наложений полигонов (комнаты не перекрывают друг друга, кроме corridor/холл).
- [ ] Коридор соединяет все комнаты (двери выходят в коридор).
- [ ] Двери на периметре (входы) помечены — они прорежут внешнюю стену.

### Этап 4 — Формирование данных этажа
Агент создаёт объект этажа по контракту `specs/data-model.md`:

```js
{
  id: 'f4',            // f + номер этажа
  level: 4,
  name: '4 этаж — Офисы',
  bounds: [1000, 640],
  rooms: [ /* массив комнат */ ],
  objects: [ /* массив объектов */ ],
}
```

#### Комната (Room)
```js
{
  id: 'f4-r1',                                  // f<этаж>-r<порядковый>
  name: 'Офис',                                 // человекочитаемое; '' если без подписи
  type: 'office',                               // см. enum типов ниже
  polygon: [[80, 60], [400, 60], [400, 270], [80, 270]],
  doors: [{ x: 230, y: 270, w: 50, side: 'bottom' }],
  windows: [{ x: 150, y: 60, w: 70 }],          // на внешних стенах
  labelAnchor: [230, 165],                       // (опц.) якорь подписи
  labelFontSize: 11,                             // (опц.) размер шрифта
  wallGaps: [{ x1: 200, y1: 270, x2: 400, y2: 270 }], // (опц.) вырез стены (открытый проход)
}
```

#### Объект (MapObject)
```js
{
  id: 'f4-c1',
  type: 'camera',
  x: 230, y: 330,
  name: 'Видеокамера 11',                        // сквозная нумерация камер
  status: 'online',
  details: { angle: 60, direction: 90, ip: '10.0.4.01', recording: true, model: 'AX-M200' },
  roomId: 'f4-r3',                              // в каком помещении (для clipPath конуса)
}
```

### Этап 5 — Вставка в building.js
1. Агент читает текущий `src/data/building.js`.
2. Добавляет новый объект этажа в массив `building.floors` (в конец, после последнего этажа).
3. **Соблюдает сквозную нумерацию:**
   - Камеры — продолжают нумерацию (если последняя «Видеокамера 10», новые — с 11).
   - Лифты/лестницы — свои номера на этаже.

### Этап 6 — Проверка
1. `npm run lint` — 0 ошибок.
2. `npm run build` — успешно.
3. В браузере: переключиться на новый этаж, проверить:
   - комнаты примыкают без зазоров;
   - внешние стены цельные (толстый контур);
   - окна прорезают внешнюю стену;
   - двери корректны (в коридор / наружу);
   - объекты на местах, конусы камер отсекаются по комнатам;
   - стиль соответствует остальным этажам.
4. Сообщить пользователю результат + что проверить вручную.

## 3. Единый стиль (обязательно для всех этажей)

Чтобы этаж был неотличим от существующих, агент применяет **те же правила**:

### Типы комнат (enum `RoomType`)
| Значение | Когда использовать | Токен цвета |
|---|---|---|
| `'hall'` | холл, вестибюль, входная группа | `--color-room-hall` |
| `'office'` | офис, кабинет, рабочая зона, кассовый зал | `--color-room-office` |
| `'meeting'` | переговорная | `--color-room-meeting` |
| `'server'` | серверная, электрощитовая (БЕЗ окон) | `--color-room-server` |
| `'service'` | санузел, служебное, лифтовой холл | `--color-room-service` |
| `'cafe'` | кафе, зона отдыха, кухня | `--color-room-cafe` |
| `'corridor'` | коридор, тамбур | `--color-room-corridor` |

### Типы объектов (enum `ObjectType`)
| Значение | Когда | Имя |
|---|---|---|
| `'elevator'` | лифт | «Лифт №N» (или «Лифт» если один на этаже) |
| `'stairs'` | лестница | «Лестница №N» |
| `'camera'` | видеокамера | «Видеокамера N» (сквозная нумерация) |
| `'atm'` | банкомат | «Банкомат X-N» |

### Правила объектов
- **Лифт + лестница** — в лифтовом холле (`type: 'service'`), в столбик на одном X,
  лифт вверху (y≈315), лестница ниже (y≈360). По холлу на каждом крыле.
- **Камеры в коридоре** — в начале и в конце, конусы навстречу (direction 90 / 270).
- **Камеры в помещениях** — `roomId` обязательен (для отсечения конуса по стенам).
- **Угол всех камер** — `angle: 60` (узкий конус).
- **Камера над банкоматами** — в углу помещения, конус направлен ровно на банкоматы.

### Правила дверей/окон
- **Двери:** `w: 30` (в холл/коридор), `w: 40` (в санузлы), `w: 50` (между крупными), `w: 80` (вход).
- **Окна:** только на внешних стенах. По периметру во все комнаты, **кроме** серверных и вестибюлей.
- **Санузлы:** «М» и «Ж» (имя из 1-2 букв), общий вход через тамбур.
- **Подписи без названия:** тамбур, санузлы, лифтовой холл — `name: ''`.

### Правила внешнего контура и стен
- Внешние стены — **тёмные толстые** (рисуются автоматически `BuildingOutline`, 8px).
- Внутренние перегородки — тонкие светлые (`#94a3b8`, 1px).
- Заливка комнат — **плоская однотонная** (без градиентов).
- Окна — прорезают внешнюю стену (белый проём + тонкая линия стекла).
- Двери на периметре (входы) — тоже прорезают внешнюю стену.

### Тени и объём (как на референсе)
Объём достигается **мягкими тенями** — это часть единого стиля, применяется автоматически:

- **Тень под каждой комнатой** — фильтр `filter-room-shadow`
  (`feDropShadow dx=0 dy=8 stdDeviation=9 floodOpacity=0.38`). Применяется к заливочному
  полигону комнаты в `Room.jsx`. Комнаты выглядят «приподнятыми» над фоном.
- **Тень под всем зданием** — фильтр `filter-floor-shadow`
  (`feDropShadow dx=0 dy=18 stdDeviation=24 floodOpacity=0.35`). Применяется к полю этажа
  в `FloorPlanSvg.jsx`. Здание в целом отбрасывает мягкую тень.
- **Направление света** — сверху (смещение по Y положительное), единое для всех теней.
- Тени **не настраиваются** для отдельных этажей — они заданы глобально в `Defs.jsx`
  и применяются ко всем комнатам/этажам одинаково. Новый этаж автоматически получает
  корректные тени без доп. действий.
- **ВИД СВЕРХУ, ТЕНИ И ОБЪЁМ — ОБЯЗАТЕЛЬНЫ** для всех элементов интерьера
  (стойки, столики, кресла, пуфики, плитка). Каждый элемент рисуется с
  `filter="url(#filter-room-shadow)"` или отдельной тенью (offset + transform).

### Элементы интерьера (features)
Комнаты могут иметь поле `features` — массив элементов интерьера. Типы:
- `counter` — барная стойка (полигон с заливкой + тень).
- `counterBar` — высокая кассовая стойка (тёмная заливка + сильная тень + кромка).
- `counterCurve` — тонкая изогнутая стойка (с тенью).
- `table` — круглый столик (круг + тень).
- `chair` — кресло (скруглённый квадрат + тень).
- `bench` — пуфик/скамейка (прямоугольник с обивкой + тень).
- `screen` — ширма/ресепшн (полупрозрачный полигон + тень).
- `partition` — внутренняя перегородка с проёмом (толстая линия + тень).
- `railing` — перила балкона (ломаная линия + тень).
- `tilePatch` — плитка другого оттенка на полу (полигон).
- `tileArc` — полукруглая плитка на полу (path).
- `tileCircle` — круглый фрагмент-акцент на полу (круг).

### Стойки с подиумом (эффект объёма)
Для стоек, которые должны выглядеть объёмно (например стойка охраны в вестибюле):
1. **Плитка-подиум** (`tilePatch`) — на 3-5 ед. шире стойки со всех сторон,
   другого оттенка (`#dbeafe`). Создаёт эффект приподнятого подиума.
2. **Сама стойка** (`counterCurve`) — с тенью. Загиб = ~10% от длины.
3. Стойка **не должна пересекать двери** — проверять координаты проёма.
4. **Вид сверху + тени обязательны** — все элементы с `filter-room-shadow`.

## 4. Шаблон запроса для пользователя

Чтобы процесс шёл гладко, пользователь даёт ввод в формате:

```
Сделай этаж: [номер] этаж — [название]
Изображение: [прикреплённый скриншот]
```

Пример:
```
Сделай этаж: 4 этаж — Бухгалтерия
[скриншот плана]
```

Агент после этого выполняет этапы 2–6 самостоятельно и отчитывается.

## 5. Чек-лист «этаж готов»

- [ ] `id`/`level`/`name`/`bounds` корректны.
- [ ] Все комнаты имеют `id`, `name`, `type`, `polygon`.
- [ ] Координаты кратны 10, в пределах 80…920 × 60…580.
- [ ] Комнаты примыкают без зазоров/наложений.
- [ ] Коридор соединяет все комнаты (двери в коридор).
- [ ] Окна на внешних стенах (кроме серверных/вестибюлей).
- [ ] Двери на периметре помечены (прорежут внешнюю стену).
- [ ] Объекты: лифты/лестницы в холле, камеры в коридоре + по помещениям, банкоматы.
- [ ] Камеры: `roomId`, сквозная нумерация имён, `angle: 60`.
- [ ] Санузлы: М/Ж через тамбур, `name: ''`.
- [ ] Тени: под каждой комнатой + под зданием (применяются автоматически).
- [ ] `npm run lint` — 0 ошибок.
- [ ] `npm run build` — успешно.
- [ ] В браузере этаж выглядит в едином стиле с остальными.

## 6. Типичные ошибки (избегать)

| Ошибка | Как избежать |
|---|---|
| Зазоры между комнатами | Округлять до 10, проверять общие рёбра |
| Наложения полигонов | Коридор не должен перекрывать комнаты; холл либо отдельный, либо `wallGaps` |
| Дверь «висит» не на стене | Координата двери = координата стены комнаты |
| Окно на внутренней стене | Окна только на периметре (x≈80/920, y≈60/580) |
| Камера без `roomId` | Конус не отсечётся по комнате — обязательно указывать |
| Дубли ID | `id` = `f<этаж>-r<н>` / `f<этаж>-<тип><н>`, проверить уникальность |
| Сбилась нумерация камер | Камеры нумеруются сквозной по всем этажам |
| Разный стиль | Использовать те же токены/тилы/толщины стен, что у существующих этажей |

## 7. Пример: ввод → результат

**Ввод пользователя:**
```
Сделай этаж: 4 этаж — Бухгалтерия
[скриншот: 4 кабинета в ряд, коридор снизу, санузел, лифт слева]
```

**Что делает агент:**
1. Анализирует скриншот → 4 офиса сверху, коридор снизу, санузел справа, лифтовой холл слева.
2. Переносит в сетку:
   - Офисы: x80-300, 300-520, 520-740, 740-920, y60-270.
   - Коридор: x80-920, y270-390.
   - Санузел + тамбур: справа снизу.
   - Лифтовой холл: x80-200, y270-390.
3. Добавляет двери (в коридор), окна (по периметру, кроме серверной), объекты
   (лифт, лестница, 2 камеры в коридоре, камеры в кабинетах).
4. Вставляет в `building.js`, проверяет, отчитывается.

**Результат:** новый этаж, визуально единый с остальными.
