# Контрибьюшен / Разработка

Правила разработки в проекте. Обязательны для людей и ИИ-агентов. Краткая версия — в
[`../AGENTS.md`](../AGENTS.md).

## Перед началом работы

Прочитай (обязательно для нетривиальных задач):

1. [`../context.md`](../context.md) — зачем проект, ограничения, инварианты.
2. [`../technical.md`](../technical.md) — зафиксированные технические решения (ADR).
3. [`../specs/`](../specs) — спецификации модулей, с которыми предстоит работать.
4. [`../plan.md`](../plan.md) — текущий этап (если вносишь код).

## Окружение

- Node.js ≥ 20, npm ≥ 10.
- `npm install` → `npm run dev`.

## Стиль кода

- **JavaScript (JSX), без TypeScript** — сознательное решение (ADR-001).
- Форматирование: Prettier (`.prettierrc` — 2 пробела, одинарные кавычки в JS, двойные в
  JSX, без точек с запятой).
- Линтинг: ESLint (flat config `eslint.config.js`).
- Именование: компоненты — PascalCase, утилиты/хуки — camelCase.
- Комментарии — на русском (как существующий код), по делу.

## Архитектурные правила

- **Состояние — MobX:** сторы-классы с `makeAutoObservable`, действия в методах стора.
  Компоненты — `observer`, доступ через `useStore()`. `useState` — только для локального UI.
- **Рендер плана — SVG** (не Canvas/Konva). Фильтры/градиенты — в едином `<defs>`, по `id`.
- **Стили — CSS Modules** + глобальные CSS-переменные темы (`src/index.css`).
- **Новые зависимости** — только с обоснованием и согласием. Не тянуть тяжёлое без нужды.

## Инварианты (не нарушать)

- ❌ Не вводить TypeScript.
- ❌ Не заменять SVG на Canvas/Konva.
- ❌ Не менять палитру/токены темы без согласования (`../specs/design-system.md`).
- ❌ Не деградировать визуальное качество плана (киллер-фича).
- ❌ Не коммитить/пушить без явного разрешения.
- ❌ Не оставлять `console.log`, закомментированный код.

## Workflow задачи

1. Прочитай релевантные спецификации/ADR.
2. Пиши код малыми шагами, проверяй в браузере.
3. `npm run lint` — без ошибок.
4. `npm run build` — проходит.
5. Обнови документацию, если изменилось поведение.
6. Отчитайся: что сделано, что проверено, что осталось.

## Чек-лист готовности PR/коммита

- [ ] `npm run lint` — 0 ошибок.
- [ ] `npm run build` — успешно.
- [ ] Нет отладочного кода.
- [ ] Код следует конвенциям и существующим паттернам.
- [ ] Если затронут план — визуальное качество сохранено/улучшено.
- [ ] Документация (`docs/`, `specs/`) актуальна.
