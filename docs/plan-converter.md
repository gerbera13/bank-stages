# Конвертер чертежей — отдельное ПО в составе приложения

> Модуль «Конвертер» — самостоятельное ПО внутри FloorPlan Studio: загрузка
> «некрасивого» чертежа → автообработка → просмотр «Было / Стало» рядом.
> Кнопка **«Конвертер»** в сайдбаре (рядом с «План»).

## 1. Что это

Отдельное ПО с циклом:

```
Загрузка чертежа (PNG/JPG)  →  Разбор геометрии  →  Просмотр «Было/Стало»
                                                          ↓
                                        Чтение подписей (необязательно)
                                                          ↓
                                         Экспорт JSON (черновик этажа)
```

Разбор ведут **два независимых движка**: векторный (§4а, по умолчанию) и старый
растровый (§4). Переключаются кнопкой прямо в конвертере.

Все приёмы обработки зафиксированы в `make-stage.md §8.5` — это единый источник
правил переноса чертежа в красивый план.

## 2. Файлы

| Файл | Роль |
|---|---|
| `src/utils/wallVectorizer.js` | **Векторный движок**, стадии 1–2: чернила → скелет → отрезки → стены |
| `src/utils/planarRooms.js` | Стадия 3: отрезки → граф → грани = комнаты и контур здания |
| `src/utils/planFeatures.js` | Стадия 4: проёмы и марши |
| `src/utils/vectorPlan.js` | Стадия 5: всё вместе → черновик этажа |
| `src/utils/planExtractor.js` | Старый (растровый) движок; из него же общий разбор содержимого комнат |
| `src/utils/labelReader.js` | Чтение подписей помещений локальной моделью (необязательно) |
| `src/utils/blueprintParser.js` | Нормализация чернового JSON в контракт `Building` |
| `src/components/Converter/Converter.jsx` | Страница конвертера (UI) |
| `src/components/Converter/Converter.module.css` | Стили страницы |

| `vite.config.js` | Проход `/lmstudio` к локальной модели |

## 3. Как пользоваться

1. Открыть приложение → нажать **«Конвертер»** в сайдбаре.
2. Перетащить чертёж (PNG/JPG) в зону загрузки или выбрать файл.
3. Геометрия извлекается автоматически (≈0.1 с на чертёж 782×352).
4. Слева — **«Было»**: исходный чертёж. Справа — **«Стало»**: красивый план
   в стиле Modern Minimal (пастельные градиенты, тени, объём).
5. **«Прочитать подписи»** — подставить названия помещений с чертежа
   (нужен запущенный LM Studio, см. §4б; ≈2 с на комнату).
6. **«Движок»** — переключить правую панель на старый разбор и сравнить.
7. **«Стены» / «Комнаты» / «Проёмы»** — показать найденное поверх исходника.
   Этими наложениями удобно понимать, почему что-то разобралось не так.
8. **«Экспорт JSON»** — скачать черновик этажа (формат `blueprint-import`);
   выгружается тот разбор, что показан справа.

## 4. Что умеет старый, растровый движок (`planExtractor.js`)

Извлечение по пикселям (без ИИ, в браузере) — **детальная прорисовка**:

| Элемент | Алгоритм | Приём |
|---|---|---|
| Ориентация | портретный чертёж разворачивается в горизонт (движок читает планы лёжа) | — |
| Режим | авто: `color` (заливки+cyan+стены) или `bw` (линии) | — |
| Стены | мажорные H/V; отсев по **плотности** (подпись ≠ стена) | — |
| Короткие перегородки | второй проход внутри комнаты: линия от стены до стены | — |
| Проёмы в стенах | разрывы ≤ 8% меньшей стороны зашиваются в маске стен | — |
| Комнаты | BW: flood-fill по мажорным стенам → доразбор перегородками | — |
| Запасной разбор | если комната накрыла весь корпус — сегментация по ВСЕМ чернилам | — |
| Контур здания | объединение прямоугольников комнат → `floor.outline` | — |
| Форма комнаты | обводка компоненты + упрощение → `polygon` (скошенные стены) | — |
| Внутр. стены | partition на всех стыках; слой `layer-inner-walls` поверх заливок | §8.5 п.7 |
| Коридор | тонкая широкая лента (≤30% высоты корпуса) + все её куски | §8.5 п.6 |
| Двери | крестики `style:'cross'` (§8.2); слой `layer-doors` поверх перегородок | §8.5 п.9 |
| Окна | Color: cyan; BW: проёмы периметра (включая торцы крыльев) | §8.5 п.4 |
| Лестница | узкая высокая комната, затем весь план; ≥5 ступеней равного шага; серая площадка на всю шахту | §8.5 п.8 |
| Двери | при запасном разборе — разрывы чернил на общих гранях комнат | §8.5 п.9 |
| Палитра | своя, «чертёжная»: жёлтые кабинеты, голубые санузлы, розоватые залы | — |
| Санузлы | маленькие комнаты с унитазом или раковиной → service | §8.5 п.2 |
| Унитаз | замкнутый овал (в т.ч. светло-серый контур), бачок к стене | §8.5 п.2 |
| Раковина | полукруг: контур замыкается только вместе со стеной | §8.5 п.2 |
| Мебель | chair/table/counter по размеру и fill-ratio, реальные w/h | — |
| Подписи | строки и блоки глифов отбрасываются: текст ≠ мебель | §8.3 |
| Перегородки | общие грани соседних комнат → partition (толстые стены) | §8.5 п.7 |

Три ошибки, которых движок больше не делает (демо `public/demo-plan.png`):
- **Дверь не склеивает комнаты.** Проём в перегородке — разрыв в маске стен,
  через который flood-fill утекал к соседям (пропадал «офис 7», сливались
  «офис 3» и «офис 2»). Проёмы зашиваются до заливки комнат.
- **Подпись — не стена.** Столбец глифов («офис 7», «11,85 м²») после склейки
  давал длинный, но дырявый вертикальный след и съедал комнату целиком.
  Вертикальные стены проверяются на плотность так же, как горизонтальные.
- **Подпись — не мебель.** Глифы собираются в строки и блоки и исключаются из
  классификации; иначе каждая подпись превращалась в кресла, а «офис 8»
  с текстом-«унитазом» — в санузел.

Ограничения (важно!):
- Результат — **черновик**: подписи сам движок не читает (для этого есть §4б),
  типы комнат назначаются
  эвристически (маленькие комнаты с сантехникой → service, коридор → corridor,
  пара самых крупных помещений → meeting — это почти всегда залы, но проверять
  надо глазами).
- Внутри движка комната — прямоугольник `x,y,w,h`: по нему считаются двери,
  перегородки, стыковка соседей и контур этажа. В отрисовку уходит настоящая
  форма: контур компоненты обводится, упрощается (Дуглас–Пекер) и отдаётся как
  `polygon`. Ломаная выдаётся, только если форма явно не прямоугольная и
  описана ≤12 вершинами — иначе это шум обводки, а не скос стены.
- Движок **автоопределяет** режим: ч/б линии или цветная схема (пастельные
  заливки + голубые окна + серо-синие стены). Цветной режим работает в браузере
  без Python; `oas/extract-plan.py` — запасной офлайн-путь.
- Тонкие стены (1px) могут путаться с проёмами — реальные чертежи обычно
  имеют стены 2..8px.
- Стены **двойной линией** (две грани и пустота между) поддерживаются: порог
  зашивки дверных проёмов берётся от типичной толщины самой стены, а не от
  ширины полосы.
- На нерегулярных планировках (коттеджи, БТИ с короткими стенами) мажорных стен
  почти нет, и корпус остаётся одной комнатой. На такой случай есть запасной
  разбор по всем чернилам: пробуются расширения 1px и 2px, берётся вариант с
  бо́льшим числом комнат, где ни одна уже не накрывает весь корпус. Двери на
  таком плане ищутся по общим граням комнат, лестница — по всему плану.
  Скошенные углы всё равно становятся прямыми: комнаты — прямоугольники.
- Перегородка распознаётся, только если упирается в стены комнаты с обеих
  сторон: выступ или ниша до середины комнаты комнату не делят.
- Цветной режим: если перегородки нарисованы очень светлым тоном, ряд кабинетов
  слипается в одну комнату — такие планы уточняются вручную.
- Яркость берётся так же, как её видит браузер: PNG с профилем `iCCP`
  конвертируется в sRGB при отрисовке в canvas, и пороги бинаризации считаются
  уже по конвертированным значениям.
- Загружать нужно **сам чертёж**, а не скриншот окна целиком: панели и ленты
  интерфейса движок принимает за помещения. Панели-полоски (тонкие и сильно
  вытянутые «комнаты») отбрасываются, но остальную ленту интерфейса движок
  всё равно разберёт как помещения.
- **Вертикальные чертежи разворачиваются на 90° по часовой стрелке** — и на
  анализ, и в панель «Было». Без разворота ломается почти всё: подписи ищутся
  горизонтальными строками, ступени — горизонтальными штрихами, коридор — низкой
  широкой лентой. Если чертёж встал «вверх ногами», разверните файл заранее.

## 4а. Новый (векторный) движок

**Движок по умолчанию.** Второй, независимый разбор того же чертежа; кнопка
**«Движок: новый / старый»** переключает панель «Стало» на старый разбор, чтобы
сравнить два результата на одном чертеже.

Почему основной именно он — на демо движки равны, а на живых чертежах разрыв
решающий:

| | старый | новый |
|---|---|---|
| демо: комнат / дверей / окон | 19 / 18 / 18 | 18 / 18 / 19 |
| коттедж: комнат / дверей | 8 / 2 | **15 / 19** |
| БТИ: комнат / дверей | 10 / 16 | **26 / 52** |
| лестниц: коттедж / БТИ | 1 / 0 | 2 (одна наружная) / 2 |

Старый точнее на аккуратных ч/б планах вроде демо и остаётся в одном щелчке.

| Файл | Стадия | Что делает |
|---|---|---|
| `src/utils/wallVectorizer.js` | 1–2 | чернила → скелет (Жанг–Суэнь) → Хаф → отрезки → пары граней = стены |
| `src/utils/planarRooms.js` | 3 | отрезки → планарный граф → грани; каждая ограниченная грань = помещение; внешняя грань = контур здания |
| `src/utils/planFeatures.js` | 4 | разрывы вдоль стен = проёмы (комната с обеих сторон → дверь, с одной → окно); марши — прямо по чернилам, без Хафа |
| `src/utils/vectorPlan.js` | 5 | всё вышеперечисленное + сантехника и мебель из `collectDetails` → черновик этажа в контракте `blueprint-import` |

Зачем он нужен: старый движок внутри себя оперирует прямоугольниками, поэтому
скошенная или трапецеидальная комната становится прямой, а марш вне здания
не находится вовсе. В новом комната приходит полигоном, контур здания —
обходом внешней грани, а наружное крыльцо становится объектом этажа.

Что уже лучше старого:
- контур здания строится обходом графа, а не объединением прямоугольников;
- наружные лестницы находятся (demo-11: 2 марша, один — крыльцо);
- комнаты — настоящие полигоны, наклон стены сохраняется;
- на нерегулярном БТИ-плане разбор идёт полностью: 26 помещений и 31 дверь
  там, где старый движок оставлял корпус почти неразрезанным.

Показатели на трёх чертежах:

| Чертёж | комнат | дверей | окон | контур | лестниц |
|---|---|---|---|---|---|
| демо (ожидается 19 / 18 / 18) | 18 | **18** | 19 | 6 точек | 1 (20 ступеней) |
| demo-11 коттедж | 15 | 19 | 10 | 10 точек | 2, одна наружная |
| demo-12 БТИ | 26 | 52 | 25 | 27 точек | 2 |

На демо не хватает одной комнаты: коридор выходит одной гранью на 10 вершин,
обходящей лестничную шахту, вместо двух кусков.

Разница в дверях на демо (15 против 18) — не пропущенные проёмы коридорных
стен: на верхней их ровно пять, движок находит все пять. Старый движок считает
дверьми ещё и разрывы в мелких перегородках (кабинки санузла).

Четыре приёма, на которых держится разбор:
- **Осевая линия — по объединению граней**, а не по среднему их концов. Грани
  двойной стены редко одной длины, и среднее обрезало стену с обоих концов.
- **Пара граней проверяется по чернилам.** У настоящей двойной стены чернила
  есть и выше осевой, и ниже. Иначе длинная стена спаривается со случайным
  обрубком (на демо — 562 px с 18 px у лестничной шахты), осевая уезжает в
  пустоту, и вся стена читается как несплошная: проёмы на ней пропадают.
- **Проём — там, где нет чернил ПО ОБЕ СТОРОНЫ от осевой.** Порог «сколько
  чернил поперёк» не работает: чертежи тянут его в разные стороны.
- **Марши ищутся ПРЯМО ПО ЧЕРНИЛАМ, без Хафа.** В маске находятся ряды подряд
  идущих чернил, соседние ряды склеиваются в ступень, ступени одинаковой ширины
  с равномерным шагом собираются в марш. Так поиск перестал зависеть от первых
  двух стадий: раньше он ломался от любой их правки, потому что порог голосов
  Хафа (25) выше длины ступени (26 px впритык) и марш держался на случайной
  диагонали через концы ступеней.
- **Шаг марша — медиана промежутков, а не «не больше трёх пикселей от
  предыдущего».** Жёсткое правило разрезало марш демо надвое посреди шахты.
- **Стопка марша компактна:** по высоте сопоставима с длиной ступени. Размерные
  засечки БТИ идут такой же равномерной пачкой — 12 штук по 19 px, растянутых
  на 326, — и без проверки план покрывался ложными лестницами.
- **Ступени марша выровнены.** Штриховка и размерные линии БТИ идут такими же
  параллельными пачками с равным шагом, но раскиданы по листу: ступень 20 px
  при разбросе 370 px. Без проверки план покрывался полосатыми лентами.
- **Коттедж даёт 15 комнат вместо ~13.** Лишние — две полоски 50×11, стоящие
  стопкой: это щели ступеней слева от распознанной части марша. Расширение
  зоны марша вдоль ступеней их не убирает: при 0.15 и 0.3 от длины ступени
  полоски остаются, при 0.5 зона съедает настоящие помещения (10 комнат из 15).
  Промежутка нет — щели стоят вплотную к реальным комнатам.
- **Щели между ступенями — не помещения.** Планарный обход честно замыкает
  каждую из них: на коттедже семь «комнат» из 21 были щелями марша 47×12.
  Зона марша тянется вдоль его хода — ПОПЕРЁК ступеней; по пропорциям
  габарита ход не определить, ступени длинные и коробка шире, чем марш длинный.
- **Вершины графа склеиваются по близости, а не по ячейке сетки.** Точка ровно
  на границе ячейки разъезжается: перегородка между «офис 5» и «офис 6» стоит
  на x=358, при шаге сетки 4 это ровно 89.5, и мельчайшая разница в дробной
  части кидала конец перегородки и конец коридорной стены в разные ячейки.
  Перегородка становилась висячей и срезалась — две комнаты сливались в одну.
- **Допуск на угол зависит от длины куска — и при склейке тоже.** Нижняя стена
  бойлерной на демо состоит из длинного куска и обрубка в 27 px, наклонённого
  на 10°. При общем допуске в 6° они не срастались, между ними оставалась дыра
  в 31 px, грань не замыкалась — и комнаты «Бойлерная» не было вовсе.
- **Допуск на угол пары зависит от длины.** У коротких отрезков Хаф меряет
  направление грубее: две грани скошенного угла коттеджа (25 и 35 px) вышли
  под 132° и 147°, при допуске 5° не спаривались и оставались двумя линиями.
- **Содержимое комнат разбирает общий код.** `collectDetails` из старого
  движка вызывается и новым: геометрия у движков разная, а «что нарисовано
  внутри комнаты» одно и то же. На демо оба дают одно и то же — 4 прибора
  и 0 предметов мебели.
- **Подписи отсеиваются по кляксам всего листа.** Раньше кляксы собирались
  покомнатно, строка подписи выходила за прямоугольник комнаты и не
  набиралась: у нового движка комнаты другие, и на демо три «стула» садились
  ровно на подписи кабинетов. Важная деталь: кляксам полного листа надо
  считать площадь внутренней дырки — по ней раковина-полукруг отличается от
  буквы. Без этого приборы уезжают в «строку текста» и сантехники на демо
  становится 2 вместо 4.
- **Проёмы ищутся с запасом ЗА концами стены.** Стена нередко обрывается ровно
  на проёме: на демо перегородка между кабинками санузла идёт x41..96, а двери
  лежат в 44..52 и 84..94 — впритык к её концам. Прежнее правило «разрыв у
  края — незакрытый конец, а не дверь» съедало их обе. Требовать по бокам от
  разрыва длинных кусков стены при этом нельзя: на коттедже и БТИ стены рваные,
  и при пороге даже в 2 px дверей остаётся 4 из 12.
- **Толщина стены — медиана нескольких промеров.** В одной точке ошибиться
  легко: середина перегородки между кабинками приходится ровно на пересечение
  с вертикальной стеной, и толщина выходила 25 px при реальных двух. Полоса
  просмотра раздувалась, и дверные разрывы в ней тонули.
- **Куски одного марша склеиваются.** Разбиение по шагу иногда рвёт стопку
  посередине: на демо марш выходил двумя лестницами по 10 ступеней в одной
  шахте. Склеиваются только те, что лежат в одном пробеге и продолжают друг
  друга, — крыльцо коттеджа с внутренним маршем не слипается.
- **Сторона комнаты определяется в координатах ПЛАНА.** Точка проёма приходила
  в координатах чертежа (0…352), а центр комнаты был в координатах плана
  (60…580): первое почти всегда меньше второго, и сторона выходила «сверху»
  почти для всех проёмов. Окна нижнего ряда рисовались на верхней стене —
  то есть внутрь коридора.
- **Ступени исключаются из поиска проёмов.** Штрих марша попадает в стены
  наравне с настоящими, и разрыв на нём становился окном: четыре лишних окна
  из двадцати двух на демо были ступенями.
- **Коридор узнаётся по числу соседей**, а не по размерам: лестничная шахта
  режет его на короткие куски, и порог по длине их не ловит. Состав помещений
  на демо совпал со старым движком (`service 5 · office 11 · meeting 2 ·
  corridor 2` против `5 · 10 · 2 · 2`).

**Подписи, слипшиеся в один кусок, становились стенами** — решено, но не с
первого захода, и путь стоит того, чтобы его записать. На демо «офис 8» даёт
кусок 35×13, а отсев текста считал глифом кусок не шире 34: промах в один
пиксель, и подпись уходила в стены, разрезая кабинет пополам.

Три попытки лечения измерены и отвергнуты — все ломали больше, чем чинили:
- **Ограничить дотягивание концов долей длины куска** (0.25) — демо встаёт
  ровно на 19 комнат, но коттедж теряет три из тринадцати. Доли 0.4 и 0.6
  демо уже не чинят.
- **Расширить рамку кандидата до целого слова** — ничего не меняет: подпись
  даёт всего одного соседа (цифру «8»), а отсев требует двух.
- **Считать словом кусок шире своей высоты и требовать одного соседа** — верхний
  ряд становится безупречным, но стен остаётся 30 вместо 46 и **пропадает
  лестница**. Уточнение «сосед на той же строке» не помогает.
Что в итоге сработало — **отсев мелких кусков, не связанных с сетью стен**.
Сеть стен здания это одна фигура во весь лист (на трёх чертежах её габарит
741×297, 485×353, 637×264), подписи лежат отдельно. Отбрасывается ровно то,
что нужно: 69 кусков на демо, все подписи. Ступени не страдают — они тонкие
(18×2 против 35×13), их спасает проверка короткой стороны.

Три раза до этого правка проваливалась, роняя лестницу, и причина оказалась
не в ней: марш держался на **случайной диагонали Хафа** через концы ступеней,
потому что порог голосов (25) выше длины ступени. Любая перемена в голосовании
эту случайность разрушала. После переноса поиска маршей прямо на чернила
отсев подписей заработал с первой попытки.

Скошенные углы пока **не воспроизводятся**: диагональные стены находятся
(на коттедже их четыре), но в контур не попадают. Угол нарисован ДВУМЯ
диагоналями, они не спариваются в одну стену, между ними замыкается щель — и
обход контура делает шип наружу и обратно вместо среза.

Прямая попытка — отсев «дотянутых» пересечений без чернил под ними — даёт на
демо ровно 19 комнат, но ломает коттедж: низ здания вываливается за контур и
вместе с ним теряется наружное крыльцо. Откачено.

**Где ломается поиск пары** (измерено). Грани угла проходят все условия с
запасом: разница углов 14° при допуске 17°, расстояние между ними 5.8 px при
допуске 26, перекрытие 22 px при нужных 12.7. Не проходит только **проверка
пары по чернилам** — ни по жёсткой маске, ни по мягкой.

Ещё две попытки, обе отвергнуты:
- **Искать пары взаимно лучшими, а не по порядку.** Первоначально я решил, что
  виноват жадный перебор: грань с меньшим номером забирает партнёра первой.
  Переписал — угол всё равно не собирается, а БТИ-план сдвигается с 26 комнат
  до 28. Значит порядок перебора ни при чём, диагноз был неверен.
- **Смягчить проверку по чернилам** — порог 0.5 → 0.35 и проба с допуском в
  пиксель (наклонная линия в растре идёт «пунктиром», точная проба мимо неё
  промахивается). Ни то ни другое пару не подтверждает, зато коттедж теряет
  комнату, а БТИ прибавляет окон.

**Настоящая причина** нашлась, когда я наконец распечатал маску вокруг угла
попиксельно вместо очередной правки порога.

Стена в этом углу нарисована **со штриховкой** — стандартный приём строительных
чертежей: две граничные линии, между ними косые штрихи, показывающие материал.
Движок находит в этой каше отрезки под 147° и 132° — и это НЕ две грани одной
стены, а штрих штриховки и кусок границы. У настоящей пары углы совпадают,
здесь разница 15°. Все шесть попыток крутили пороги, пытаясь соединить то, что
парой не является.

Настоящая стена там видна на распечатке: горизонтальные линии y=212 и y=220
обрываются на x≈42 и x≈45 — стена толщиной около 8 px, дальше уходящая по
диагонали вниз-влево с той же толщиной.

Отсюда задача на будущее формулируется иначе: не «починить сопоставление
граней», а **научиться читать штрихованные стены** — распознавать штриховку как
заливку между границами, а не как набор линий. Это отдельная работа, и она
поможет не только со скосами: штрихуют и обычные стены.

Первая проба — **морфологическое замыкание всей маски** (расширить, затем
сжать), чтобы промежутки штриховки затянулись, а дверные проёмы остались.
Отвергнуто: замыкание склеивает и то, что склеивать нельзя. Радиус 2 роняет
коттедж с 15 комнат до 8 и теряет наружное крыльцо; радиус 1 — до 9, а БТИ
раздувается с 26 комнат до 31. Демо при этом даже улучшается (19 комнат), но
цена несоразмерна.

Значит замыкать надо **не всю маску, а только там, где штриховка найдена**.
Проба распознать её по плотности чернил в окне тоже не удалась: у штриховки
0.53–0.63 в окне 7×7, у сплошной стены 0.71 и 0.14 в разных местах, у тонкой
перегородки 0.29. Диапазоны перекрываются, порога не существует.

Третья проба — искать штриховку как **пучок отрезков** одного наклона с мелким
шагом, тем же приёмом, что и ступени марша. Не годится: в зоне угла на стадии
отрезков всего ДВА отрезка, никакого пучка. Штриховка в пикселях есть, но до
этой стадии не доходит — порог голосов Хафа (30 для коттеджа) отсекает короткие
штрихи ещё раньше.

Итого три измеренных отрицания, и все три сходятся в одном: **штриховку надо
распознавать на растре, до Хафа**. К стадии отрезков от неё остаются только
случайные обрывки, и любой приём, работающий с отрезками, обречён. Порог тоже
не подобрать — ни по плотности, ни по размеру.

Что это значит для работы: нужен отдельный проход по маске, ищущий регулярный
косой узор (автокорреляция или подсчёт переходов чернила/фон вдоль направления),
и заливка найденных участков перед скелетизацией. Полноценный заход, а не
правка.

Что осталось несделанным:
- **Скошенные углы** — см. выше, разобрано и отвергнуто четыре подхода.
- **Комнат на демо 18 против 19** — коридор выходит одной гранью, обходящей
  лестничную шахту, вместо двух кусков. Похоже, это не ошибка: между коридором
  и шахтой на чертеже стены нет, а старый движок разделяет их только потому,
  что оперирует прямоугольниками.
- **Окон на демо 19 против 18** — расхождение в одно.
- **Типы помещений** назначаются эвристикой: подписи движок не читает, для
  этого есть отдельная возможность (§4б).

## 4б. Чтение подписей локальной моделью

Единственное, чего пиксельный разбор не может в принципе: движок находит
геометрию до пикселя, но букв не читает, и каждый план после конвертации
переименовывается руками. Кнопка **«Прочитать подписи»** в конвертере снимает
эту работу. Возможность **необязательная**: нет модели — конвертер работает
как прежде.

| Файл | Роль |
|---|---|
| `src/utils/labelReader.js` | нарезка комнат и запросы к модели |
| `vite.config.js` | проход `/lmstudio` → `http://localhost:1234` |

Что нужно: запущенный **LM Studio** с загруженной моделью, умеющей смотреть
картинки (проверено на `qwen3-vl-8b-instruct`). Модель ищется сама — берётся
первая, в имени которой есть `vl`, `vision`, `llava`.

Приёмы, каждый добыт измерением:
- **Спрашиваем по одной комнате, а не про весь план.** Дать модели чертёж
  целиком и попросить координаты — не работает: подписи она читает верно, но
  кладёт их в свою внутреннюю сетку (на демо `y=456` при высоте кадра 352).
  Геометрию мы и так знаем точно, поэтому спрашиваем только «что здесь
  написано».
- **Режем по полигону комнаты, снаружи забеливаем.** С запасом наружу в кадр
  попадает подпись соседа (комната получала чужое «офис 8»), с отступом внутрь
  обрезается собственная (пропадали «офис 8» и «Бойлерная»).
- **Числа с дробной частью и через дробь отбрасываются.** На БТИ-плане приходили
  «3.12», «251/4.6», «35 1/2» — это размеры и площади. Целое число оставляем:
  помещения на планах БТИ нумеруются, и «132» — законная подпись.
- **Запрос идёт через дев-сервер.** Напрямую браузер к LM Studio не пустит:
  тот не отдаёт CORS-заголовков и не отвечает на preflight-запрос `OPTIONS`.

Что получается:

| Чертёж | Прочитано | Время |
|---|---|---|
| демо | **12 из 12**: «Конференц зал», «Бойлерная», «офис 1…11», «Центр офисных и бухгалтерских услуг РФПМП» | ~45 с |
| demo-11 коттедж | 1 («Кабинет») — на чертеже подписей почти нет | ~14 с |
| demo-12 БТИ | 3 номера помещений: 132, 409, 12 | ~50 с |

На демо читаются **все 12 подписей**. «Бойлерная» и «офис 6» сначала терялись,
но это были пробелы **геометрии**, а не чтения: комнат просто не было среди
найденных. После починки склейки коротких кусков стены и склейки вершин по
близости комнаты появились — и подписи пришли сами, ничего не трогая.

## 5. Масштабирование

Извлечённые координаты переносятся в сетку приложения 1000×640:
- комнаты вписываются в рамку 80..920 × 60..580 (как make-stage.md §1);
- масштаб — равномерный `min(840/w, 520/h)`, центрирование по осям.

## 7. Проверка

Быстрая проверка в браузере: **`?demo=1`** открывает конвертер с загруженным
демо-чертежом (`public/demo-plan.png`, 782×352).

Что должно выйти на нём у каждого движка:

| Показатель | Векторный (по умолчанию) | Старый |
|---|---|---|
| Время | ~90 мс | ~100 мс |
| Комнат | 18 | 19 |
| Дверей | 18 | 18 |
| Окон | 19 | 18 |
| Сантехника | 4 прибора: 2 унитаза, 2 раковины-полукруга | то же |
| Мебель | 0 (на чертеже её нет — только подписи) | 0 |
| Лестница | 1 марш, 20 ступеней | 21 ступень, серая площадка на всю шахту |
| Коридор | одна грань, обходящая шахту | 2 куска ленты, разрезанной шахтой |
| Контур | 6 точек, Г-образный | 6 точек, Г-образный |
| Подписи | все 12 читаются (§4б) | не читаются |

**Проверять надо и раскладку проёмов по сторонам, а не только их число.** Ошибка,
из-за которой все окна нижнего ряда рисовались внутрь коридора, количества не
меняла вовсе: окон было 19, дверей 18 — ровно сколько ожидалось, — а сторона у
всех выходила «сверху». Ни одна проверка по счётчикам её не ловила, нашлась она
только глазами на картинке. Ожидаемая раскладка на демо:

| | сверху | снизу | слева | справа |
|---|---|---|---|---|
| окна | 7 | 11 | 1 | — |
| двери | 12 | 2 | 2 | 2 |

На двух живых чертежах (`public/demo-11.png` коттедж, `public/demo-12.png` БТИ)
разрыв решающий — таблица в §4а.

Быстрая проверка движков вне браузера — скрипты в песочнице разработки: разбор
трёх чертежей и сравнение с этими числами.
