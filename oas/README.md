# OAS-файлы «Меридиан»

OAS-Layout документы Бизнес-центра «Меридиан», сгенерированные из мок-данных
`src/data/building.js`.

| Файл | Этаж | Уровень |
|---|---|---|
| `meridian-f1.layout.json` | 1 этаж — Холл | `level_f1` (0 мм) |
| `meridian-f2.layout.json` | 2 этаж — Офисы | `level_f2` (3600 мм) |
| `meridian-f3.layout.json` | 3 этаж — Технический | `level_f3` (7200 мм) |

Регенерация: `node oas/convert.mjs` (скрипт `oas/convert.mjs`).

## SVG-превью

Для каждого layout-файла генерируется SVG-превью (`meridian-f*.svg`) по правилам
OAS-Render (`node oas/render.mjs`):

- масштаб 2 px/мм, Y инвертирован на границе рендера (данные не меняются);
- группы слоёв `oas-rooms`, `oas-walls`, `oas-openings`, `oas-labels` (+ `oas-furniture`);
- стены — линии с `stroke-width = thickness × scale`; двери/проходы — белые проёмы,
  окна — голубые; мебель и банкоматы/камеры/лифты — упрощённые фигуры;
- камера рисуется с маркером направления взгляда (`rotation_deg`, 0° = вверх).

Превью можно открыть в браузере: `open oas/meridian-f1.svg`.

## Что перенесено

- **Комнаты** → `rooms` с `boundary_polygon` (замкнутый, единый порядок обхода — CCW),
  `area_m2` (по формуле Гаусса) и `usage` по типу помещения (`lobby`, `cafe`, `office`,
  `meeting`, `server_room`, `sanitary`, `storage`, `circulation`).
- **Стены** → `walls`: строятся из общих рёбер комнат. Рёбра режутся по всем точкам
  пересечения (концы рёбер соседних комнат + границы проёмов), фрагменты с одинаковым
  набором соседних комнат сливаются в одну стену. Толщина 160 мм (рендер: strokeWidth 8),
  перегородки (`partition`) — 60 мм (strokeWidth 3).
- **Двери/окна** → `openings`: `in_wall` + `position_along_wall_mm` от начала стены.
  Двери: 2100 мм высотой; окна: 1500×900 мм (sill 900). Проём, пересекающий угол комнаты,
  обрезается к стене (см. «Известные упрощения»).
- **`wallGaps` и `partition.doorGap`** → `openings` с `type_name: "Passage Opening"`
  (`is_fixed: true`, `operation: "fixed"`).
- **Мебель (features)** → `furniture`: столики, стулья, скамейки, барные стойки
  (`casework`), ширмы (`fixture`).
- **Объекты** → `furniture` (type `fixture`): лифты, лестницы, банкоматы, видеокамеры.
  `rotation_deg` камер = азимут взгляда (`details.direction`): 0° = +Y, положительное —
  по часовой стрелке от +Y (совпадает с исходной SVG-конвенцией).
- **Контур здания** → `floor_slabs` (по одному на уровень).
- **Связность** → `connections` (`direct`) для всех дверных проёмов между помещениями;
  проходы (Passage Opening) между комнатами тоже образуют `connections`.

## Ключевые решения конвертации

- **Масштаб**: 1 SVG-ед = 20 мм (`SCALE` в `convert.mjs`). Даёт реалистичные размеры:
  дверь 50 ед → 1000 мм, коридор 120 ед → 2400 мм, этаж ~18,4 × 12,8 м.
- **Система координат**: исходные данные — Y-down (SVG, viewBox 1000×640); в OAS —
  Y-up: `y' = (640 − y) · 20`. Инверсия выполнена на данных, не в рендере.
- **Перепад этажей** 3600 мм принят условно (в источнике этажности нет).

## Известные упрощения

- Декоративные элементы пола (`tileCircle`, `tilePatch`) и подписи (`labelAnchor`)
  не переносятся — это визуальный слой, не архитектурные сущности.
- Операционные данные объектов (`ip`, `cash`, `lastService`, `status` и т.п.)
  не входят в OAS; статус продублирован в `furniture.tags`.
- Проём, пересекающий угол комнаты (дверь через стык стен), обрезается к той стене,
  где лежит большая часть проёма — ширина проёма может уменьшиться.
- На 3 этаже комнаты `f3-r1` (Серверный зал) и `f3-r2` (Электрощитовая) перекрываются
  в исходных данных — перенесены как есть, их общие стены имеют `adjacent_rooms`
  из обеих комнат.
- `connections` направленные (от помещения с дверью), без транзитивных «through».
