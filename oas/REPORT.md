# Отчёт о работе: программирование поэтажных планов (OAS-экспорт и SVG-рендер)

**Проект:** bank-stages — интерактивный просмотрщик поэтажных планов здания
(Бизнес-центр «Меридиан»), Vite 8 + React 19 + MobX, SVG-рендер планов.
**Период:** сессия 02.08.2026.

---

## 1. Цель

Обработать существующий мок-контент поэтажных планов (`src/data/building.js`)
средствами стандарта **Open Architecture Standards (OAS)** и получить:

1. Машинно-читаемые OAS-Layout документы (JSON) для всех этажей;
2. Качественные SVG-превью планов по правилам OAS-Render.

Вторичная цель — проверить применимость OAS-скилов (oas-core, oas-geometry,
oas-layout, oas-render, oas-extensions, oas-program) на реальных данных проекта.

## 2. Подготовка

### 2.1 Установка OAS-скилов

Скилы из репозитория `open-architecture-standards-2d-floor-plans` установлены
глобально, чтобы быть доступными в любом проекте:

- `~/.config/opencode/skills/oas-{core,extensions,geometry,layout,program,render}/SKILL.md`
- справочная документация — `~/.config/docs/{core,extensions,geometry,layout,program,render}.md`
  (относительные ссылки `../../../docs/…` из скилов разрешаются корректно).

Замечание: скилы подхватываются opencode только после перезапуска; в текущей сессии
работа велась по их содержимому из документации.

### 2.2 Изучение исходных данных

- `src/data/building.js`: 3 этажа, комнаты с полигонами, двери/окна (координата —
  **центр** проёма, `side` — сторона), `wallGaps` (проходы-вырезы в стенах),
  `features` (мебель), `objects` (лифты, лестницы, банкоматы, камеры).
- `specs/data-model.md`: контракт модели (координаты — Y-down SVG, viewBox 1000×640).
- Рендер приложения: стены — strokeWidth 8, перегородки — 3, двери — белый проём +
  дуга открывания, окна — вырез + линия стекла.

### 2.3 Изучение OAS

Прочитаны `docs/core.md`, `docs/geometry.md`, `docs/layout.md`, `docs/render.md`:

- геометрия — целые миллиметры, Y-up, замкнутые полигоны с явным `closed: true`,
  единый порядок обхода, площадь — производное значение `area_m2`;
- layout — уровни (`levels`), комнаты, стены (прямые сегменты `from`/`to`),
  проёмы (`in_wall` + `position_along_wall_mm`, валидация `pos + w ≤ длина стены`),
  плиты перекрытий, мебель, `connections`;
- render — один масштаб на план, инверсия Y на границе рендера, слои
  `oas-rooms`/`oas-walls`/`oas-openings`/`oas-labels`, порядок отрисовки,
  «рендерер не выдумывает геометрию».

## 3. Реализация

### 3.1 Конвертер `oas/convert.mjs`

Программа преобразует `src/data/building.js` → OAS-Layout JSON. Ключевые решения:

| Решение | Значение | Обоснование |
|---|---|---|
| Масштаб | 1 SVG-ед = 20 мм | реалистичные размеры: дверь 1000 мм, коридор 2400 мм, этаж ~18,4×12,8 м |
| Система координат | Y-down → Y-up: `y' = (640 − y)·20` | требование OAS-Geometry, инверсия выполнена в данных |
| Толщина стен | 160 мм / перегородки 60 мм | соответствует strokeWidth 8/3 рендера |
| Перепад этажей | 3600 мм (0/3600/7200) | принят условно, в источнике этажности нет |
| Высота проёмов | двери 2100, окна 1500, подоконник 900 | типовые значения |

Алгоритм построения стен:

1. Все рёбра комнат (и перегородки `partition`) собираются как сегменты;
2. Каждый сегмент режется по всем точкам пересечения (концы рёбер соседних комнат +
   границы проёмов) — это корректно обрабатывает **частично общие рёбра**
   (например, стена холла 1600–8000 мм и стена кафе 8000–12800 мм на одной линии);
3. Фрагменты с одинаковым набором соседних комнат сливаются в «прогон» = одна стена
   с `adjacent_rooms`;
4. Проём ищет прогон с максимальным пересечением; если проём пересекает угол комнаты
   (стык двух прогонов), он обрезается к границам выбранного прогона (таких две двери —
   на 2-м и 3-м этаже, ширина 1000 → 900 мм);
5. Каждый проём валидируется: `position_along_wall_mm ≥ 0` и
   `position_along_wall_mm + width_mm ≤ длина стены`.

Специфичные сущности:

- **`wallGaps`** и `partition.doorGap` → `openings` типа «door» с
  `type_name: "Passage Opening"`, `is_fixed: true`, `operation: "fixed"`;
- **мебель** (`table`, `chair`, `bench`, `counter`, `screen`) → `furniture`
  с `position`/`dimensions` или `footprint`;
- **объекты** (лифт, лестница, банкомат, камера) → `furniture` (`type: "fixture"`),
  `rotation_deg` камер = азимут взгляда (0° = +Y, по часовой — как в исходных данных);
- **контур здания** (`outline`) → `floor_slabs`;
- **связность** → `connections` (`direct`) для всех дверных проёмов между комнатами;
- операционные данные (`ip`, `cash`, `lastService`, `status`) в OAS не входят —
  статус продублирован в `furniture.tags`.

### 3.3 SVG-рендер `oas/render.mjs`

По правилам OAS-Render:

- масштаб 2 px/мм, инверсия Y на границе рендера (данные не меняются);
- слои-группы: `oas-rooms`, `oas-walls`, `oas-openings`, `oas-furniture`,
  `oas-labels`, `oas-annotations`;
- порядок: пол здания → заливки комнат → стены → проёмы → мебель → подписи;
- стены — линии с `stroke-width = толщина × масштаб`;
- **двери**: створка + дуга открывания (четверть окружности, 24 точки),
  направление открывания — внутрь помещения (point-in-polygon по `connects_rooms`);
  двойные двери (≥ 1600 мм) — две створки;
- **окна**: белый вырез + линия стекла; **проходы**: вырез с пунктирной рамкой;
- подписи комнат: название + площадь, центроид с поправкой на площадь
  (корректен и для вогнутых полигонов);
- масштабная линейка 2 м.

Стиль (итерация по требованию «тени + пастель»):

- пастельная палитра: комнаты — линейные градиенты по `usage`
  (насыщенный верх → светлый низ), стены — мягкий сланец;
- тени `feDropShadow` (объявлены один раз в `<defs>`): пол здания, комнаты, мебель;
- видеокамеры — фиолетовые, банкоматы — зелёные.

## 4. Ключевые проблемы и их решение

1. **Частично общие рёбра комнат** (стена «кафе—коридор» — подмножество стены
   «холл—коридор»): решено разбиением рёбер на атомарные фрагменты по всем точкам
   пересечения. Первая реализация содержала ошибку оси (константная/изменяемая
   координата) и сравнение длины в разных единицах — обнаружено встроенной
   валидацией, исправлено.
2. **Проём через угол комнаты** (дверь 1000 мм на стыке двух прогонов с разными
   наборами комнат): выбор прогона по максимальному пересечению + обрезка проёма.
3. **Проём в перегородке** (одна комната с двух сторон) изначально помечался как
   выход на `exterior` — исправлено через флаг перегородки.
4. **Конвенция координат**: дверь в данных — центр проёма, в OAS — `position`
   от начала стены; пересчитано с учётом обрезки к краям стены.

## 5. Качество и проверки

- `npm run lint` — 0 ошибок; `npm run build` — проходит;
- встроенная валидация `convert.mjs`: ссылочная целостность (`in_wall`),
  геометрическая вложенность проёмов, целочисленность координат;
- `render.mjs`: отсутствие `NaN`/`undefined` в SVG, соответствие счётчиков
  сущностей (дуг/створок/окон/проходов) данным.

## 6. Известные упрощения

- Декоративные элементы пола (`tileCircle`, `tilePatch`) и якоря подписей
  (`labelAnchor`) не переносятся в OAS (визуальный слой, не архитектурные сущности);
- на 3-м этаже комнаты `f3-r1` (Серверный зал) и `f3-r2` (Электрощитовая)
  перекрываются в исходных данных — перенесены как есть;
- `connections` направленные, без транзитивных маршрутов (`through`);
- перепад этажей 3600 мм — допущение.

## 7. Итоги и дальнейшие шаги

  (вертикальные связи лифтов/лестниц);
- расширение рендера: конусы обзора камер, аннотации, интерактивные слои.
